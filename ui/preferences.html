Detection

Turns on by itself when the file name or the container metadata clearly says the video is VR — for example …_180x180_3dh_LR.mp4, …_MKX200.mp4, or a file whose stereo layout is tagged in the container.

Accepts a bare 180/360 or a headset name in the file name as enough, provided the frame's shape agrees. More catches, more false positives.

View

degrees across

How wide a slice of the sphere fills the window to begin with. Higher shows more at once; much above 120° the edges start to stretch the way a very wide lens does.

Controls

Scroll to zoom. The top and bottom strips of the window stay untouched so the title bar and playback controls keep working — adjust them below if your controls sit elsewhere.

Performance

An upper bound. VR2D already limits itself to what the source can actually resolve — a 1440-wide eye covering 180° holds about 8 pixels per degree, so a 105° view is worth roughly 840 of them, and rendering far past that costs time without adding detail. Lower this if panning still feels heavy.

per second, or 0 to pace automatically

Every pan step makes the projection map be recomputed, at roughly 0.06 s of CPU per megapixel rendered — so the affordable rate depends on how large a window you are filling. Left at 0, VR2D works it out from the current size. It costs nothing once you stop moving.

Safe areas

Height in points, measured from the top and bottom of the window, where dragging is ignored so IINA's own controls stay clickable.
